# Обработка данных ВЭЖХ-МСВР: что делает фреймворк и как запустить его на своём компьютере

Документ описывает, что делает обработка (раздел 1), как запустить её на своём компьютере (разделы 2–5) и как подготовить новые файлы .raw, чтобы они обсчитывались так же, как выборки из 94 и 104 проб (раздел 6). Подробное описание этапа MS-DIAL — в СОП: `sop/СОП_обработка_ВЭЖХ-МСВР_данных.docx`.

---

## 1. Что происходит при обработке

Вся обработка выполняется одной командой. Все пороги и правила хранятся в файле `pipeline/config.py`, данные о пациентах — в `metadata/*.csv`. Случайные операции (кросс-валидация, перестановки) используют фиксированное начальное значение, поэтому повторный запуск на тех же файлах даёт те же числа.

**Шаг 1. Загрузка данных.** Читаются таблица MS-DIAL и метаданные: группа, пол, возраст, включение или исключение и его причина. Инъекции QC и бланки распознаются по имени. Пробы с `include = 0` (диагноз вне дизайна) в анализ не входят.

**Шаг 2. Фильтрация признаков.**
- Признак должен обнаруживаться не менее чем в 80 % QC и не менее чем в 50 % проб хотя бы одной группы.
- Если в таблице есть бланки, медиана сигнала в QC должна быть не менее чем в 5 раз выше медианы в бланках.

**Шаг 3. Межсерийная коррекция** (если образцы измерялись несколькими сериями, как в s107). Значения каждой серии умножаются на отношение медианы всех QC к медиане QC этой серии, отдельно для каждого признака. Качество коррекции оценивается по тому, сколько признаков различаются в QC разных серий до и после неё.

**Шаг 4. Воспроизводимость.**
- Удаляются признаки с RSD в QC больше 30 %.
- Дрейф внутри серии проверяется тестом с исключением по одной инъекции QC (leave-one-QC-out): сравнивается ошибка без коррекции и с коррекцией LOWESS. Коррекция включается параметром `DRIFT` в `pipeline/config.py`; в s266 и s107 она не применялась, так как не уменьшала ошибку.

**Шаг 5. Нормализация на разведение мочи.**
- Основной метод — PQN: в качестве эталона берётся медианный спектр QC.
- Для сравнения считается MSTUS.
- Пробы с очень низким фактором разведения (< 0,2) отмечаются отдельно.

**Шаг 6. Импутация и логарифмирование.** Пропуски заполняются половиной минимума признака, затем данные переводятся в log₂.

**Шаг 7. Объединение ионов в соединения.** Признаки с разницей времени удерживания не более 0,02 мин и корреляцией ρ ≥ 0,8 считаются ионами одного соединения: аддуктами, изотопами или фрагментами из источника. Дальше статистика считается по соединениям, а не по отдельным ионам.

**Шаг 8. Экзогенные сигналы.**
- **Индекс экзогенного сигнала.** Он строится по гомологическому ряду алкилдиэтаноламинов — сигналу контейнеров и условий сбора. Пробы делятся на группы с высоким и низким индексом.
- **Категории соединений.** Лекарства, пища, табак и контаминанты определяются по курированному списку и ключевым словам. Категория из чужих аннотаций (отчёта, статьи) сохраняется, только если её подтверждают данные.

**Шаг 9. Одномерная статистика.** Для каждого соединения:
- строится модель log₂(интенсивность) ~ группа + пол + возраст + индекс; p-значения корректируются по Бенджамини–Хохбергу (q);
- пары 1:1 подбираются по возрасту внутри пола, разности в парах проверяются критерием Уилкоксона для связанных выборок;
- пациенты сравниваются с контролями, у которых индекс низкий;
- проверяется, что контроли с высоким и низким индексом не различаются. Если соединения нет ни у одного контроля, условие считается выполненным.

**Шаг 10. Правило «находки».** Соединение считается находкой, если:
- q < 0,05;
- p < 0,05 в подобранных парах и против контролей с низким индексом, с тем же направлением изменения;
- контроли с высоким и низким индексом не различаются;
- соединение не экзогенное.

**Шаг 11. Классификация.**
- Пятикратная кросс-валидация повторяется 20 раз; отбор пяти соединений идёт внутри каждого обучающего фолда.
- Модели: логистическая регрессия на этих пяти соединениях и PLS-DA; значимость проверяется 1000 перестановками.
- Для сравнения строятся базовые модели «только пол» и «только индекс».
- Те же модели оцениваются в подобранных парах.

**Шаг 12. Аннотации.**
- Для курированных кандидатов проверяется соответствие формулы, иона и m/z, затем присваивается уровень MSI 1–4.
- Маркеры прошлых работ сверяются с данными: сохраняется ли направление изменения, значимость, проходят ли все критерии.

**Шаг 13. Анализы чувствительности и пути метаболизма.**
- Повторный расчёт с MSTUS вместо PQN.
- Расчёт без сильно разведённых проб.
- Пути метаболизма — mummichog (только справочно).

**Шаг 14. Отчётные материалы.**
- Таблицы Excel и CSV, рисунки PNG, TIFF и PDF.
- Для s107 — `Tables_s107.xlsx` и проверка соединений статьи ABC.
- Для s266 — пакет статьи в `submission_analytica/`.
- Глава диссертации собирается из этих результатов.

| | |

Время полной обработки на 4-ядерном ПК: s107 — около 40–60 мин, s266 — около 1–1,5 ч. Дольше всего идут перестановочные тесты и кросс-валидация.

## 3. Получение программы и данных

**Программа.**
1. Откройте на GitHub репозиторий `avolorf/metab`.
2. Выберите ветку `claude/metabolomics-hplc-ms-processing-ktvooo`.
3. Нажмите **Code → Download ZIP** и распакуйте архив в папку без кириллицы и пробелов в пути, например `C:\metab`.

Если установлен git, можно склонировать репозиторий:
```
git clone -b claude/metabolomics-hplc-ms-processing-ktvooo https://github.com/avolorf/metab.git
```

**Исходные данные** в репозиторий не входят: в них есть персональные сведения. Скопируйте их в папку `data/` внутри программы, точно с такими путями и именами:

| файл | для чего |
|---|---|
| `data/s266_table_for_calc.csv` | таблица MS-DIAL выборки s266 |
| `data/raw_check/*.mzML` и `data/raw_check/injections.csv` | необязательно: проверка бланков s266 |
| `data/s107/s107_table.csv` | таблица MS-DIAL выборки s107 |
| `data/s107/table_nastya.csv` | 30 маркеров отчёта первого этапа (табл. 20) |
| `data/s107/res_annotated_2.csv` | альтернативные аннотации признаков s107 |
| `data/abc/T1_ABC_markers_in_s107.xlsx` | необязательно: таблица соединений статьи ABC |

Метаданные (`metadata/`), курация (`curation/`, `curation_s107/`) и параметры уже лежат в репозитории.

## 4. Первый запуск

**Windows.** Дважды щёлкните по файлу `Запуск_Windows.bat`.

**macOS / Linux.** Откройте терминал в папке программы и выполните `bash run_mac_linux.sh`.

При первом запуске создаётся окружение `.venv` и устанавливаются пакеты из `requirements.txt` (3–10 мин). Затем открывается меню:

```
  1. Проверить установку и исходные файлы
  2. Обработать выборку s107 (около 40–60 мин)
  3. Обработать выборку s266 (около 1–1.5 ч)
  4. Быстрый пробный прогон s107 (несколько минут)
  5. Пересобрать главу диссертации
  6. Полный цикл: s266 -> s107 -> глава
  7. Конвертировать экспорт MS-DIAL в таблицу
  8. Новая выборка: подготовить из экспорта MS-DIAL
  9. Обработать новую выборку
  0. Выход
```

Рекомендуемый порядок:
1. **Пункт 1.** Утилита покажет, все ли пакеты установлены и каких файлов не хватает.
2. **Пункт 4.** Пробный прогон за несколько минут проверит, что всё работает. Его результаты пишутся в отдельную папку `results_quick_s107/` и основные результаты не затрагивают.
3. **Пункт 2 или 3** — полная обработка. Перед запуском утилита попросит подтвердить, что результаты будут пересозданы.

Те же действия доступны из командной строки:
- на Windows — `Запуск_Windows.bat run s107`;
- на macOS / Linux — `bash run_mac_linux.sh run s107`;
- в уже активированном окружении — `python metab.py run s107`.

Все команды выводит `python metab.py --help`.

Каждый шаг пишет журнал в папку `logs/`. При ошибке утилита называет файл журнала, в котором её искать.

## 6. Подготовка новых файлов .raw, чтобы они обрабатывались так же, как 94 и 104 пробы

Обработка в утилите начинается с **экспорта выравнивания MS-DIAL**. Чтобы новая выборка обсчитывалась тем же алгоритмом и по тем же критериям, нужно соблюсти три условия:

1. одинаково измерить и назвать файлы;
2. обработать их в MS-DIAL с теми же параметрами;
3. экспортировать таблицу в том же виде.

Всё, что идёт после экспорта, утилита делает сама, ровно как для s266 и s107: фильтры, коррекция серий, нормализация, индекс экзогенного сигнала, правило находок, классификация.

> Выборки s266 (94 участника) и s107 (104 пробы) я обрабатывал начиная с таблиц, которые вы уже экспортировали из MS-DIAL. Этап MS-DIAL выполнялся в вашей лаборатории. Поэтому для полной сопоставимости с ними лучше всего взять **файл параметров тех проектов MS-DIAL**: сохранённый проект `.mdproject` или экспорт параметров. Если его нет, используйте значения из таблицы в п. 6.3 — это параметры из таблицы 3 отчёта НКР (с двумя дополнительными аддуктами, см. ниже).

Полное описание с обоснованием — в СОП `sop/СОП_обработка_ВЭЖХ-МСВР_данных.docx`. Ниже — краткий порядок действий.

### 6.1. Измерение

- **Те же метод и прибор:** колонка, градиент, положительная ионизация, DDA MS/MS, диапазон m/z 150–1500. Изменение градиента сдвигает время удерживания. Утилита это учитывает (сдвиг экзогенного ряда определяется автоматически), но сравнивать соединения с прежними выборками станет сложнее.
- **Объединённый QC** — смесь равных аликвот всех проб этой выборки. Его вводят в начале каждой серии, затем через равные промежутки и в конце серии. В s107 QC вводили после каждых 6 проб, но шаг может быть и другим (например, 8 или 10 проб): алгоритм от него не зависит, утилита берёт фактический порядок инъекций из MS-DIAL (п. 6.3). Важно лишь число QC: в каждой серии их должно быть не меньше 5, иначе ненадёжны фильтр «признак есть в ≥ 80 % QC», оценка RSD и коррекция серий (для проверки межсерийного сдвига нужно минимум 3 QC в серии).
- **Бланки растворителя** — перед каждым QC. Схема серии: `Blank → QC → N проб → Blank → QC → … → Blank → QC`, где N — выбранный шаг (6, 8, …).
- **Рандомизация.** Порядок проб в серии случайный, а группы (пациенты и контроли) представлены в каждой серии в сопоставимых долях. Иначе межсерийный сдвиг смешается с различием групп.
- **Пробоподготовка и хранение** одинаковы для пациентов и контролей: моча до манипуляций, −80 °C (или хотя бы одинаковые условия), одинаковые пробирки.

### 6.2. Имена файлов и журнал инъекций

- Имена файлов — только латиница, без пробелов:
  - пробы `S001`, `S002`, … — номер совпадает с номером в таблице пациентов;
  - QC: `QC01`, `QC02`, …;
  - бланки: `Blank01`, `Blank02`, ….
- Нумерация QC и бланков сквозная по всем сериям, номера не повторяются.
- Ведите журнал последовательности (Excel): файл, тип (Sample/QC/Blank), группа, номер серии, порядковый номер инъекции.

### 6.3. MS-DIAL (версия 5.5)

1. **Конвертация.** Если MS-DIAL не открывает .raw напрямую, сконвертируйте файлы в mzML программой ProteoWizard msconvert:
   `msconvert *.raw --mzML --32 --zlib --filter "peakPicking vendor msLevel=1-" -o mzML/`
2. **Новый проект.** File → New project: Soft ionization, Chromatography (LC), Conventional LC/MS или DDA, MS1 и MS2 — Centroid, Positive, Metabolomics.
3. **Импорт файлов.** Импортируйте **все** файлы — пробы, QC и бланки. В таблице файлов заполните по журналу для каждого файла:
   - **Type:** Sample / QC / Blank;
   - **Class ID:** группа — например `Control`, `BC`, `PC`;
   - **Batch:** номер серии;
   - **Analytical order:** порядок инъекций.

   Эти поля попадают в экспорт, и утилита берёт из них серии и порядок инъекций. Контрольную группу лучше сразу назвать `Control`.
4. **Параметры** (если нет файла параметров прежних проектов):

| Раздел | Параметр | Значение |
|---|---|---|
| Data collection | MS1 / MS2 tolerance | 0.01 / 0.025 Да; m/z 150–1500, весь градиент |
| Peak detection | Minimum peak height | 100 000 |
| | Mass slice width | 0.1 Да |
| | Smoothing | линейно-взвешенное скользящее среднее, 15 сканов |
| | Minimum peak width | 10 сканов |
| MS2Dec | Sigma window / MS2 abundance cut-off | 0.5 / 0 |
| Identification | Библиотека | NIST HR-MS/MS (.msp), без использования RT |
| | Dot-product cut-off (simple / weighted) | 600 / 600 |
| | Matched spectrum percentage / min. peaks | 25 % / 3 |
| Adducts | Положительный режим | [M+H]⁺, [M+Na]⁺, [M+K]⁺, [2M+H]⁺, [2M+Na]⁺, [M+NH₄]⁺, [M+H−H₂O]⁺ |
| Alignment | Reference file | QC из середины серии |
| | RT / MS1 tolerance | 0.1 мин / 0.015 Да |
| Фильтрация | Remove features based on blank information | да (проба ≥ 5 × бланк) |
| | **Gap filling by compulsion** | **нет** |
| Normalization | метод | **none** (нормализует утилита) |

   Аддукты [M+NH₄]⁺ и [M+H−H₂O]⁺ добавлены к перечню прежних проектов: в них регистрируются глюкурониды. Если нужна строгая идентичность с s266/s107, оставьте перечень аддуктов как в тех проектах.

   **Заполнение пропусков и нормализацию в MS-DIAL не включайте.** Утилита делает их сама. Если включить их в MS-DIAL, данные обработаются дважды и не будут сопоставимы с прежними выборками.
5. **Контроль.** Data processing → All processing. Проверьте выравнивание на 5–10 соединениях, присутствующих во всех пробах (креатинин, гиппуровая кислота), и наложите хроматограммы QC разных серий. Сохраните проект.

### 6.4. Экспорт из MS-DIAL

Export → Alignment result:
- **Raw data matrix (Area)**, без нормализации;
- **отметить QC и бланки** — они нужны для фильтров и коррекции серий;
- если доступны, включить столбцы о спектрах MS/MS: MS/MS assigned, MS/MS matched, Total score. По ним утилита ставит уровень MSI 2;
- формат — текст с табуляцией (.txt).

### 6.5. Обработка в утилите

1. Пункт меню **«Новая выборка: подготовить из экспорта MS-DIAL»** или команда:
   ```
   python metab.py new s300 --export s300_alignment_area.txt --sample-pattern "(\d+)$"
   ```
   - `s300` — любое имя латиницей.
   - `--sample-pattern` берёт номер пробы из конца имени файла (`S007` → `7`).
   - Если контрольная группа в MS-DIAL называется не `Control`, `Контроль`, `Healthy` или `КГ`, укажите её: `--control ИМЯ`.
   - Шаг QC указывать не нужно, если в MS-DIAL заполнены Analytical order и Batch: порядок берётся оттуда. Если они не заполнены, укажите шаг и серии вручную, например `--qc-every 8 --batches 1-40,41-80` (в меню утилита спросит об этом сама).

   Утилита сама:
   - создаёт таблицу `data/s300/s300_table.csv` и журнал инъекций;
   - создаёт заготовку метаданных `metadata/metadata_s300.csv`, где контроль назван `Control`, а остальные группы — как в MS-DIAL;
   - находит экзогенный ряд диэтаноламинов и определяет сдвиг его времени удерживания. Если ряд не найден, индекс отключается, и модель строится по полу и возрасту;
   - берёт серии и порядок инъекций из проекта MS-DIAL;
   - записывает все настройки в `datasets/s300.json`.

   Сравнения задаются автоматически: каждая группа против контроля и группы пациентов между собой.
2. **Метаданные.** Откройте `metadata/metadata_s300.csv` (Excel → сохранить как CSV UTF-8) и заполните:
   - `sex` — M или F;
   - `age` — возраст;
   - `include` — 1 или 0;
   - `exclude_reason` — причина исключения, например другой диагноз.
3. **Пробный прогон** (несколько минут, отдельная папка): `python metab.py run s300 --quick`.
4. **Полная обработка:** `python metab.py run s300` или пункт меню **«Обработать новую выборку»**. Результаты окажутся в `results_s300/`: `results.xlsx`, `tables/`, `figures/`, `log.txt`.

Все пороги и правила — фильтры QC, RSD, PQN, импутация, модель с поправками, подобранные пары, правило находок, кросс-валидация, перестановки — те же, что для s266 и s107. Они берутся из `pipeline/config.py`. При необходимости отдельные значения для новой выборки можно поменять в `datasets/s300.json`.

Если у новых соединений есть подтверждённые аннотации (стандарт, совпадение MS/MS, проверенная формула), занесите их в `curation_s300/candidates_curated.csv` — так же, как это сделано для s266 и s107. Утилита проверит формулу и ион и присвоит уровень MSI.

## 7. Типичные проблемы

| сообщение | что делать |
|---|---|
| «Не найден Python» (Windows) | установите Python 3.13 с python.org, отметив **Add python.exe to PATH**, и запустите `.bat` снова |
| ошибка при установке пакетов | проверьте интернет; удалите папку `.venv` и запустите снова. За прокси организации: `pip install --proxy http://адрес:порт -r requirements.txt` |
| «Не хватает файлов: data/…» | скопируйте исходные данные (раздел 3); имена и регистр букв должны совпадать |
| глава собралась только в .md | установите pandoc и повторите пункт 5 меню |
| предупреждения `findfont: Font family … not found` | безвредны: рисунки строятся шрифтом по умолчанию. Для полного совпадения со статьёй установите шрифты Liberation Sans |
| «MemoryError» или очень долгий расчёт | закройте другие программы. Для пробы используйте быстрый прогон; в `pipeline/config.py` можно временно уменьшить `N_PERM` (это меняет p перестановочных тестов) |
| результаты отличаются в 3-м знаке | версии пакетов отличаются от `requirements.txt`; для точного совпадения установите указанные версии |

При каждом запуске папки `results/` и `results_s107/` пересоздаются, а файлы в `report_s107/` и `submission_analytica/` перезаписываются. Если нужно сохранить предыдущие результаты, скопируйте их заранее.
